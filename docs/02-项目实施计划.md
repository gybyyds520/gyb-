## 二、总体技术架构

```
┌─────────────── 表现层（三端） ───────────────┐
│ Web(Vue3+Vite) │ Electron 桌面端 │ 移动端(响应式网页版) │
└──────────── 统一 API + WebSocket/SSE ────────┘
                        │
┌─────────────── 应用层（Spring Boot 3.2.5） ───────────────┐
│ 学情数据 │ 学生画像 │ 预测分析 │ 预警中心 │ 干预工单 │ 报表 │ 系统管理 │
└──────────────────────────┬──────────────────────────────┘
┌─────────────── 服务层 ───────────────┐
│ 大模型适配层（Ollama 多模型路由/降级/SSE 流式） │ RAG 检索 │
│ 预测模型服务（Python scikit-learn，模型文件 + HTTP 推理） │
│ 规则引擎 │ 消息推送 │ 报告生成 │
└──────────────────────────┬──────────────────────────────┘
┌─────────────── 数据层 ───────────────┐
│ MySQL 8（业务数据） │ Redis（缓存/会话） │ 本地模型库（Ollama + .pkl） │
└──────────────────────────────────────┘
```

### 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 构建工具 | Maven Wrapper | 本机无 Maven，wrapper 可提交到仓库，答辩机也免配置 |
| 前后端 | 前后端分离，同源部署 | 桌面端 Electron 直接加载构建产物 |
| ML 集成 | Python 训练离线产出 `.pkl`，Java 侧用 **ONNX 或 PMML** 加载；备选 Python FastAPI 推理微服务 | 避免 Java 侧重复实现算法；毕设演示稳定性优先 |
| 大模型 | Ollama HTTP API（`llama3.2` 主 / `qwen2.5` 备）+ SSE 流式 | 开题报告既定方案 |
| 三端 | 一套 Vue3 代码 + 响应式布局 → Web 与移动端；Electron 复用同一套产物 | 保证"三端统一架构"落地且不增加 3 倍工作量 |
| 缓存 | Redis，未就绪时降级为 Caffeine | 降低环境阻塞风险 |

## 四、分阶段实施计划

### Phase 0｜环境与工程骨架（2026.10 中下旬，约 1.5 周）

**任务**
1. 安装/配置：启动 Ollama 并拉取 `llama3.2`；确认 Redis；生成 Maven Wrapper
2. 初始化后端工程：Spring Boot 3.2.5 + MyBatis-Plus + Spring Security + JWT + Redis
3. 初始化前端工程：Vue 3 + Vite + Element Plus + ECharts + Pinia + Vue Router
4. 统一返回结构、全局异常处理、日志、Swagger/OpenAPI 文档
5. Git 分支规范与提交规范

**产出**：后端可启动并返回健康检查；前端可登录页渲染；`README.md`

**里程碑 M0**：`http://localhost:8080/actuator/health` 与前端 dev server 均正常

---

### Phase 1｜数据层与学情数据管理（10 月下 ~ 11 月中，约 3 周）

**任务**
1. 数据库设计（约 20 张表）：
   - 基础：`sys_user` `sys_role` `sys_menu` `student` `teacher` `clazz` `course` `term`
   - 学情：`score` `attendance` `class_performance` `online_behavior`
   - 画像：`profile_snapshot` `student_tag` `tag_definition`
   - 预测：`ml_model` `prediction_result` `feature_record`
   - 预警：`warning_rule` `warning_record` `intervention_ticket` `intervention_log`
   - 系统：`notify_message` `audit_log` `import_task` `data_quality_report`
2. MyBatis-Plus 实体与 Mapper 生成
3. 学生/课程/成绩/考勤/行为 CRUD + 分页查询
4. **Excel 批量导入**（EasyExcel）+ 模板下载 + 校验报告
5. **模拟数据生成器**（一键生成 ~500 学生 × 多学期演示数据）
6. 数据质量校验（缺失/越界/重复/一致性）+ 字段级脱敏

**产出**：数据管理模块可用，500 条演示数据可导入

**里程碑 M1**：导入一份 Excel 成绩后，质量报告与列表查询正确

---

### Phase 2｜学业预测与预警引擎（11 月中 ~ 12 月初，约 3 周）

**任务**
1. **特征工程**：历史成绩（均分、趋势、标准差）、出勤率、作业完成度、在线学习时长、课堂表现分、学分进度
2. **模型训练**（Python）：LogisticRegression / RandomForest / XGBoost 三模型对比，输出 Accuracy/Precision/Recall/F1/AUC/RMSE
3. **模型导出**：优先导出 ONNX，Java 侧加载推理；备选 FastAPI 推理服务
4. **预测服务**：批量预测 + 单学生预测，结果入库，含风险分与等级
5. **可解释性**：SHAP 特征贡献 → 存入 `prediction_result.explain_json`
6. **四级预警规则引擎**：蓝/黄/橙/红，阈值与评分卡可视化配置、规则组合、去重抑制
7. **实时推送**：WebSocket/SSE 推送预警
8. **模型管理**：版本、指标看板、上线/回滚

**产出**：预测模型 + 预警规则引擎

**里程碑 M2**：对演示数据批量预测，预警名单与人工抽样一致率 ≥ 80%

---

### Phase 3｜Ollama 大模型分析服务（12 月初 ~ 12 月中，约 2 周）

**任务**
1. Ollama 适配层：统一接口、多模型路由（llama3.2 主 / qwen2.5 备）、超时降级、SSE 流式输出
2. **提示词模板管理**：模板 CRUD + 版本 + 变量注入
3. **预测结果解释**：SHAP + LLM 转述为自然语言归因
4. **学情报告生成**：个人/班级/课程三档模板，导出 Word（poi-tl）/ PDF
5. **个性化学习建议**：按强弱项生成可执行清单
6. **RAG 问答助手**：培养方案/课程大纲/校规文档切片入库，检索增强回答并标注出处
7. **AI 治理**：Token 用量统计、调用日志、敏感词过滤

**产出**：AI 分析服务 + 报告导出

**里程碑 M3（中期检查）**：核心链路打通——导入数据 → 预测 → 预警 → AI 生成报告

## 六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| Maven 未安装 | 阻塞后端 | 用 Maven Wrapper；或安装 Maven 3.9 |
| Redis 未就绪 | 阻塞缓存 | Docker 启动；或降级 Caffeine，保留接口不变 |
| 本地算力不足，llama3.2 推理慢 | 演示卡顿 | 用 `llama3.2:1b`/量化版；SSE 流式改善体验；结果缓存；必要时云端降级（开题报告已写） |
| ONNX 集成成本高 | 阻塞预测服务 | 备选 Python FastAPI 推理微服务，Java 侧 HTTP 调用 |
| 真实学情数据缺失 | 模型效果无说服力 | 模拟数据生成器 + 公开数据集（如 UCI Student Performance）辅助验证，论文中如实说明 |
| 1000 用例压力大 | 影响 G6 | 参数化 + 数据驱动为主，避免手写重复；提前在 Phase 1 起同步写测试 |
| 三端工作量翻倍 | 延期 | 一套 Vue3 代码复用，移动端走响应式；Electron 仅做壳 |
| 论文与实现不一致 | 答辩风险 | 每 Phase 结束同步更新论文章节，避免最后补写 |
