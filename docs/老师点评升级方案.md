# 老师点评升级方案：数据源训练 · 本地大模型部署 · 外部 AI 接入

> 针对答辩老师点评的核心疑问：
> ① 系统的数据源是什么、预测模型怎么训练？② 本地大模型部署会不会"无法成功训练"？③ 是否需要接入外部 AI？
> 本方案给出澄清口径 + 落地升级（已实现部分用 ✅ 标注）。

---

## 一、问题一：数据源与训练（预测模型怎么训练）

### 1.1 现状（已实现，回答"怎么训练"）

| 环节 | 实现 | 说明 |
|---|---|---|
| 特征构建 | `PredictionService.buildFeatures()` | 从成绩、考勤、课堂表现、在线行为等表聚合 16 项特征（均分、趋势、标准差、出勤率、作业完成度、参与度、视频进度等） |
| 训练数据 | `PredictionService.buildTrainingDataset()` | 遍历历史学期：用第 N 学期特征 + **第 N+1 学期是否挂科** 作为标签（有监督信号），形成训练集 |
| 模型训练 | `ml/`（Python scikit-learn / XGBoost） | LR / RF / XGB 三模型对比、交叉验证、指标评估（accuracy / F1 / AUC），产出 `models/*.joblib` + 元信息 |
| 推理链路 | Java → ML 服务 `/ml/predict` | 实时特征 → 模型推理 → 风险分级 + 预测得分 |
| 冷启动兜底 | `ConstantPredictor` + 规则引擎 | 训练样本过少/单类别时自动兜底，保证功能可用 |

### 1.2 数据来源分层（回答"数据源是什么"）

| 来源 | 用途 | 状态 |
|---|---|---|
| 教务系统真实历史数据 | 生产环境主数据源（成绩/考勤等） | `xqfx.acad.provider` 已留接口，`mock` 为演示实现，可切换真实对接 |
| 演示数据引导（bootstrap） | 空库启动自动生成 200 名学生演示数据 | ✅ 已实现（`auto-demo`） |
| 实时数据流（realtime） | 定时模拟新考勤/在线行为/预警，驱动"启动即实时" | ✅ 已实现 |
| 批量导入接口 | 成绩批量导入、质量校验 | ✅ 已实现 |

### 1.3 升级项 A：训练数据源诊断接口 ✅（本次实现）

新增 `GET /api/ml/dataset-summary`，让管理员/答辩现场直接展示训练数据健康度：

- 可用样本数（当前可构成训练集的学生 × 学期组合数）
- 类别分布（风险 1 / 非风险 0 各多少条）
- 学期跨度（覆盖几个历史学期，训练集的时间范围）
- 特征覆盖率（每项特征非空比例）
- 数据状态判定：`READY`（样本充足）/ `COLD_START`（样本过少，建议开启演示数据/接入真实数据）
- 建议动作文案（如"当前样本 380 条、类别均衡，可支撑 LR/RF/XGB 训练"）

> 口径说明：训练数据 = 历史学期特征 + 下学期结果标签，这是经典的**监督学习时间序列切分**方式，不依赖任何外部标注；演示环境数据由引导程序生成，生产环境切换到真实教务数据即可。

## 二、问题二：本地大模型部署（"无法成功训练"的澄清）

### 2.1 概念澄清（答辩口径）

老师担心的"训练"分两种，必须区分：

| 类型 | 是否需要做 | 说明 |
|---|---|---|
| **大模型预训练**（从零训练 LLM，需千卡级算力） | **不需要** | 系统部署的是**开源预训练大模型的推理服务**，直接加载官方已训练好的模型权重（如 llama3.2:3b 量化版），不做从零训练 |
| **预测模型训练**（ML 监督学习） | 需要且已在做 | 见第一部分，LR/RF/XGB 用学校历史学情数据训练，消费级算力秒级完成 |

### 2.2 本地部署可行性（已实证）

| 项目 | 实测/配置 |
|---|---|
| 模型 | `llama3.2:3b`（量化），主模型；`qwen2.5-coder:1.5b` 兜底；`nomic-embed-text` 向量 |
| 硬件 | 16GB 内存个人电脑即可运行（当前项目机器已跑通） |
| 部署 | Ollama 本地服务 `http://127.0.0.1:11434`，HTTP + SSE 流式接入 ✅ |
| 健康检查 | `GET /api/ai/health`、`/api/ai/models` ✅ |

### 2.3 升级项 B：AI 健康接口返回 Provider 状态（本次实现 ✅）

`/api/ai/health` 增强为返回：

```json
{
  "localModel": "llama3.2:3b",          // 本地模型是否可用
  "localAvailable": true,
  "cloudConfigured": false,             // 是否配置了外部 AI
  "cloudAvailable": false,
  "activeProvider": "LOCAL",            // LOCAL / CLOUD / RULE_FALLBACK
  "providerMode": "auto"                // auto=本地优先云端兜底
}
```

> 如需"训练"本地大模型做领域微调：消费级硬件可采用 **LoRA 微调**（如 llama3.2:3b 用 16G 内存可训），远不需要从零预训练；本系统当前采用"预训练模型直接推理 + 提示词工程 + RAG 知识库"路线，成本最低、效果可控。

## 三、问题三：外部 AI 接入（双轨策略，本次实现 ✅）

### 3.1 策略：本地优先 + 云端自动降级（可选接入）

```
用户请求 → 本地 Ollama（llama3.2:3b）
              ├─ 可用 → 直接回复（数据不出校）
              └─ 不可用/超时/报错
                    ├─ 已配置云端 API → 脱敏后转外部 AI（status=CLOUD_FALLBACK）
                    └─ 未配置/云端也失败 → 规则化降级（status=FALLBACK）
```

- 默认 `xqfx.llm.provider=auto`：**本地优先**，数据不出校是默认路径；
- 只有本地不可用时才按需**脱敏**（姓名/学号/手机号等敏感字段打码）后走云端；
- 未配置 api-key 时云端通道自动关闭，行为与现状一致（零风险升级）；
- 调用日志 `ai_call_log` 记录 provider 来源，可审计"哪次请求走了云端"。

### 3.3 配置示例

```yaml
xqfx:
  llm:
    provider: auto            # auto=本地优先云端兜底 | local=仅本地 | cloud=仅云端
  ollama:
    fallback-to-cloud: false    # 本地不可用时允许转云端；填入 api-key 后改为 true
  llm:
    cloud:
      # 免费推荐：智谱 GLM-4.7-Flash（输入/输出/缓存长期免费，200K 上下文，OpenAI 兼容）
      # 领取 key：https://open.bigmodel.cn 控制台创建 API Key
      base-url: https://open.bigmodel.cn/api/paas/v4
      api-key: ""                           # 留空则云端通道关闭（零风险默认）
      model: glm-4.7-flash                  # 备选：deepseek-chat / qwen-turbo（按量付费）
      timeout: 60s
  privacy:
    mask-llm-prompt: true      # 出校提示词脱敏（姓名/学号/手机/身份证）
```

## 四、验收口径

1. `mvn test` 通过（含新增 RemoteLlm 与 AiAnalysisService 云端降级用例）；
2. 本地 Ollama 关闭时：`/api/ai/report` 返回 `CLOUD_FALLBACK`（已配置云端）或 `FALLBACK`（未配置）；
3. `/api/ml/dataset-summary` 返回当前训练集样本数、类别分布与状态判定；
4. 未配置 api-key 时云端通道不启用、行为与升级前一致（向后兼容）。
