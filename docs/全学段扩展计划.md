# 全学段扩展计划：从高校学情分析预警系统 → 覆盖小学 / 初中 / 高中 / 大学

> 版本：v1.0 · 2026-10-18 · 依据当前代码基线（git `50676d2`）
> 目标：在不推倒现有架构的前提下，把「高校学情分析预警系统」扩展为**全学段学情分析与预警平台**，
> 以「学段化配置 + 平台化底座」为核心思路：现有能力全部保留，差异通过配置与适配层表达。

---

## 一、目标与边界

| 项 | 内容 |
|---|---|
| 愿景 | 一个平台覆盖小学→大学全学段，每学段按自身规律配置指标、规则、角色、界面 |
| 边界 | 不做内容教学（题库/课程制作），专注**学情分析与预警闭环**（现有强项），内容类只做数据接入 |
| 形态 | 单校多学段优先（一个学校实例可配小学/初中/高中/大学学段），预留多校多租户 |
| 复用 | 现有全部能力平移：预警引擎、预测、画像、AI 报告、智能体、大屏、监察中心、导出、通知、通讯 |

## 二、学段差异盘点（需求来源，逐项影响设计）

| 维度 | 小学（1-6） | 初中（7-9） | 高中（10-12） | 大学（现有） |
|---|---|---|---|---|
| **学制/年级** | 6 年制 | 3 年制 | 3 年制 | 本科 4 / 专科 3 |
| **学科体系** | 语数英+科学/道法/音体美，低年级弱分数 | 全科 9 门，中考导向 | 选科 3+1+2/3+3、等级赋分、合格考 | 培养方案、必修/选修、学分制 |
| **成绩形态** | 等级制（优秀/良好…）、低年级评语 | 百分制+排名 | 原始分+**等级赋分** | **GPA 绩点**、百分制 |
| **预警侧重** | 行为习惯、课堂表现、作业完成、兴趣特长、体质健康 | 学科均衡、偏科、青春期心理、升学预警 | 选科适配、赋分变动、升学路径（强基/综评/艺体） | GPA、挂科风险、欠学分、学籍预警、就业深造 |
| **角色** | 班主任、科任、教导处、校长 | 班主任（更重）、心理老师 | 班主任、选科导师、年级组 | 辅导员、学院、教务、学工（现有） |
| **家长参与** | 极高（监护人、接送、习惯养成） | 高（学业监督） | 中（升学决策） | 低（现有绑定子女+回执） |
| **学生主体** | 未成年人，**信息保护最严** | 未成年人 | 未成年人（16+ 部分成年） | 成年人 |
| **数据来源** | 校讯通/一卡通/考勤/家校平台 | 教务/考试系统 | 教务/新高考系统 | 教务系统（现有 Acad 适配器） |

**三个硬约束（由学段差异引出，贯穿全篇）**：
1. **组织模型要抽象**：现有 `college→major→clazz` 是大学语义，K12 是 `school→grade→clazz`，需统一为组织树（OrgNode）。
2. **指标/规则要学段化**：预警阈值、权重、触发条件不能写死，需按学段配置。
3. **未成年人合规**：K12 数据采集、展示、导出受《个人信息保护法》《儿童个人信息网络保护规定》约束（监护人授权、最小化采集、脱敏展示、监护人查询权）。

## 三、架构改造方案（按层，与现有代码映射）

### 3.1 数据模型层（新增/改造表）

| 改造 | 现有对应 | 方案 |
|---|---|---|
| **school 学校/租户** | 无（单校） | 新增 `school` 表；`sys_user`、`student`、`teacher` 加 `school_id`（默认 1） |
| **学段配置** | `sys_config` | 新增 `stage` 枚举（PRIMARY/JUNIOR/SENIOR/UNIVERSITY）；`school.stage` 决定学校学段 |
| **组织抽象** | `college/major/clazz` | 抽象为统一组织树：`org_node(id,parent_id,org_type=SCHOOL|CAMPUS|GRADE|CLAZZ|COLLEGE|MAJOR,code,name,stage)`；现有 `clazz` 增加 `grade` 标准化与 `org_node_id` 映射（**迁移兼容：保留原表，新增映射字段**） |
| **学科字典** | `course`（课程） | 新增 `subject_dict(subject_code,name,stage,grade_range)`；`course` 关联 `subject_id` 与学段 |
| **成绩模型** | `score` | 增加 `score_type`（PERCENT/GRADE/LEVEL/GPA）、`raw_score`、`standard_score`（学段内标准化）、`level`（优良中差/ABC）、`gpa`（大学）；`exam` 增加 `exam_type`（单元/期中/期末/模拟/等级考/合格考/竞赛） |
| **指标定义** | `academic_indicator`（写死） | 新增 `metric_def(metric_code,stage,type,category,formula)`；按学段加载指标库 |
| **规则模板** | `warning_rule` | 改造为 `rule_template(stage,metric,operator,threshold,weight,trigger,action)`，学校初始化时按学段实例化 |
| **画像标签** | `tag_definition` | 标签字典按 `stage` 分组（小学"学习习惯"、中学"偏科/心理"、大学"就业深造"） |
| **监护关系** | `student_parent` | 增加 `guardian_consent`（监护人授权记录，K12 必填）、`consent_time` |

### 3.2 服务层（规则/范围/预测学段化）

| 服务 | 改造 |
|---|---|
| `DataScopeService` | 数据范围从 `visibleStudentIds` 扩展支持 `school_id / grade / org_node` 层级；K12 班主任=班级、年级组=年级、校长=全校；大学保持现有院系体系 |
| 预警引擎（`WarningService`） | 规则从数据库模板加载（`rule_template` 按 stage 过滤），阈值/权重/触发学段化；K12 支持"偏科指数、赋分变动、习惯行为"新指标；大学保留 GPA/欠学分 |
| 预测服务（`PredictionService`） | 特征工程学段化：大学用 GPA/学分/选课特征；中学用学科成绩+偏科+波动；小学用行为/习惯/课堂表现特征（数据稀疏，降级为规则+简单模型） |
| 成绩换算（新增） | `ScoreNormalizer`：百分制↔等级制↔GPA 按学段换算规则（高中等级赋分算法单列，新高考公式可配置） |
| 家长服务（`ParentService`） | 增加监护人合规校验：K12 绑定需录入监护人授权；家长通知/报告按学段分级（小学每日习惯反馈、中学考试报告、大学预警） |

### 3.3 AI 层（本地 Ollama 学段化）

- 提示词模板（`ai_prompt_template`）增加 `stage` 字段：小学报告用通俗语言+给家长的建议；中学强调分数与策略；大学保持现有学术风。
- 知识库（`knowledge_doc`）增加 `stage` 标签：补充 K12 学科知识/考点/政策（新高考赋分规则、中考政策）。
- 智能体（`AiAgent`）按学段加载模板+知识库子集；学情报告/归因/评语全部走学段化 prompt。
- 预测/归因模型输入特征学段化（与 3.2 联动）。

### 3.4 展示层（角色菜单与端体验）

- `RolePermissionService` 矩阵增加 `stage` 维度：同一角色在不同学段渲染不同菜单（如"试卷分析"高中才显示"赋分"、"选科"；大学显示"培养方案/学分"）。
- 前端布局 `layout/index.vue` 按学段切换：K12 端新增"班主任工作台、教导处看板"；家长端增强（K12 子女习惯/作业/体质/家长会）；学生端分龄（小学极简卡片、中学完整、大学现有）。
- 大屏/监察中心支持 school/grade 切换与多学段指标。

### 3.5 接入层（数据源适配器）

- 现有 `AcadSystemAdapter` 抽象升级为 `SchoolDataSourceAdapter`：定义统一接口（学生/教师/班级/成绩/考勤/行为数据拉取），按学段实现对接（校讯通、智学/阅卷平台、一卡通、教务系统）；保留 Mock 适配器供演示。

## 四、合规与安全（K12 专属，必须前置）

1. **监护人授权**：K12 学生注册/数据采集须家长授权（`student_parent.guardian_consent`），无授权不采集行为类数据。
2. **最小化采集**：K12 不采集身份证号等敏感信息，仅学号+姓名+必要联系。
3. **脱敏展示**：未成年人照片/手机号在教师端默认脱敏；导出需二次授权。
4. **角色分级**：班主任看本班、年级组看本年级、校领导看全校；家长仅看自己子女。
5. **数据留存**：K12 数据最小必要留存，按政策配置保留期。

## 五、分阶段实施路线（每阶段遵循：实现→单测→全量测试→README→git 提交）

| 阶段 | 名称 | 范围 | 交付物 |
|---|---|---|---|
| **P0** | 平台学段化底座 | `school`+`stage`+组织树抽象+学科/指标/规则模板学段化+ScoreNormalizer（百分/等级/GPA 换算）+数据范围扩展 | 数据层+规则引擎学段化，大学现状零回归 |
| **P1** | 中学（初中/高中） | 成绩接入（百分/等级/排名）、偏科与波动预警、班主任工作台、心理/升学预警、家长端增强、选科与赋分（高中） | 初高中可演示闭环 |
| **P2** | 小学 | 行为/习惯/课堂表现指标、体质健康、极简学生端、监护人合规（授权/脱敏）、家校互动（通知/回执/成长档案） | 小学演示闭环+合规 |
| **P3** | 多校与商业化 | 多租户隔离（school 级数据隔离与账号隔离）、大屏/监察多校切换、SaaS 订阅或私有化部署包 | 可售形态 |

**依赖顺序**：P0 → P1 → P2（P1/P2 可并行推进）；P3 依赖 P0 完成。

## 六、关键决策点（需你拍板，影响 P0 设计）

1. **多校还是单校多学段**？——影响 school 表与租户隔离设计（推荐：先单校多学段，P3 再多校）。
2. **部署形态**：私有化交付（学校内网）还是 SaaS？——影响多租户与 OAuth/外部系统对接策略。
3. **K12 数据来源**：是否已有明确对接系统（校讯通/智学/一卡通）？——决定 P1 接入适配器优先级。
4. **学生端年龄分级**：小学生端是否需要独立极简 App/页面，还是统一 Web 门户分龄皮肤？
