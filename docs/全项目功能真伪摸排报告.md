## 一、API 层静态交叉核对（前端调用 ↔ 后端路由）

方法：`audit_api_crosscheck.py` 提取前端 `web/src/api/*.js` 全部 `request.method('path')` 调用，与后端 25+ Controller 路由（class 级 `@RequestMapping` + 方法级 `@XxxMapping`，含模板路径归一化）比对。

- 前端调用数：**202**
- 后端路由数：**202**
- 精确匹配：**196**
- 名义未匹配：**6**（全部人工核实为脚本正则漏捕，后端接口真实存在）：
  1. `POST /homework`、`POST /mistake`、`POST /performance`、`POST /student` —— Controller 方法用无路径注解的 `@PostMapping`，正则未捕获；
  2. 前端 `encodeURIComponent` 拼接的动态路径（如 `/course-space/materials/{id}/file`）。

**结论：API 层无"前端调用但后端无实现"的空壳接口。**

另有 6 条后端路由未被前端调用（`/ai/logs`、`/auth/refresh`、`/course-space/materials/{p}/file`、`/score/template`、`/student/template`、`/sys/configs/{p}`），其中模板下载类多为通用工具接口，属"供未来/管理端备用"，非缺失。

## 二、空壳按钮扫描（事件绑定 ↔ 函数实现）

方法：`audit_button_scan.py` 对 **32 个 .vue** 提取 template 事件绑定名，与 script 内定义函数比对。

- 疑似未定义 handler：**2 处**，人工核实均为误报：
  1. `fileInput.click()` —— DOM 原生调用，非事件 handler；
  2. `go` —— script 中确有定义（跨行定义未被正则捕获）。

**结论：无"点了没反应"的空壳按钮。**

## 四、摸排发现并修复的真 bug

### 问题现象
教师按教学班（offeringId=4，clazz_id 为 NULL）发布章节测验后，学生端**能看到该测验**（`/homework/offering/mine` 可见），但**提交被拒**：`HomeworkService.submit()` 中 `student.getClazzId().equals(hw.getClazzId())` 对 offering 测验（clazz_id=null）恒不成立 → 抛 FORBIDDEN「该作业不属于你的班级」。

同时 `GlobalExceptionHandler` 将 BusinessException 以 **HTTP 200 + JSON 业务 code** 返回，导致按 HTTP 状态判读的脚本误判为"提交成功"，而数据库核实无任何 submission 记录、教师端统计 submitted=0。

### 修复内容（commit `076e686`）
1. `HomeworkService.submit()` / `studentDetail()` 校验改为 `studentCanAccess()`：
   - offering 测验：学生 ∈ 该教学班（`course_enrollment` 选课 ∪ offering.clazz_id=学生行政班，复用 `CourseSpaceService.offeringStudents`）；
   - 普通班级作业：维持原 clazzId 相等校验（null 安全）。
2. 新增单测 2 例：offering 测验选课学生可提交；非选课学生拒绝。
3. README 同步章节测验权限说明。

### 修复验证
- `HomeworkServiceTest` 全部通过；
- 全量 `mvn test` 通过（exit=0）；
- 8081 最新代码实例重跑 e2e：学生提交 biz=200「提交成功，客观题已自动批改」，教师统计 submitted=1 / avg=20.0，数据库 submission 记录落库。

### 附带提示（非 bug）
业务异常统一以 HTTP 200 + 业务 code 返回（对前端 axios 统一拦截友好）；第三方/脚本调用方需以响应体 `code` 字段判成败，勿只认 HTTP 状态码。
