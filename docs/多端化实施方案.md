# 多端化实施方案（Web / 微信小程序 / 移动端 / 桌面端）

> 目标：让「学情预测分析系统」覆盖 Web 网页端、微信小程序端、移动端（手机小屏）与 Windows 桌面端四个形态；其中小程序端与移动端页面必须适配手机小屏，移动端界面参照学习通、作业帮等成熟教育 App 的交互设计。
> 原则：本地化、免费优先；最大化复用现有前后端代码；分批实施、每批可交付可验证。

---

## 一、现状盘点

| 项 | 现状 |
|---|---|
| 后端 | Spring Boot 3.2.5（Java 17，端口 8080，context-path `/api`），REST + JWT（`xqfx_token`），角色权限矩阵（管理员/教师/辅导员/学生/家长），本地 Ollama 提供 AI 能力 |
| Web 前端 | Vue3 + Vite + Element Plus（`web/`），PC 桌面优先布局（左侧分组菜单 + 内容区），登录/注册/课程空间/作业/试卷录入/学情/预警等全部功能已就绪 |
| 数据库 | MySQL `xqfx`，含课程（course_offering）、作业、试卷题库、签到、讨论、通知等全部业务表 |
| 部署 | 本地开发（dev proxy 127.0.0.1:8080），前端可 `npm run build` 产出静态 `dist/` |

**结论**：后端是纯 REST API，天然与前端形态解耦，多端只需各自提供界面并复用同一套 API 与鉴权；Web 端是功能最全的"母版"，其余端做裁剪与适配。

---

## 二、四个端的形态规划

| 端 | 形态 | 定位 | 页面要点 |
|---|---|---|---|
| 1. Web 网页端 | 现有 Vue3 应用（保真升级） | 教师/管理员/辅导员的完整工作台（大屏操作） | 保持现有左侧菜单布局，补充响应式兜底 |
| 2. 移动 H5 / 移动端 | 同一 Web 应用的小屏适配（或 uni-app 编译 H5） | 手机浏览器即开即用；后续可打包 App | 底部 Tab 导航、卡片流、大点击区 |
| 3. 微信小程序端 | uni-app 编译微信小程序 | 学生/家长高频轻操作（看课、签到、作业、预警） | 底部 Tab（首页/课程/消息/我的），参照学习通 |
| 4. Windows 桌面端 | Electron 打包现有 Web | 教师/管理员桌面快捷入口，无需开浏览器 | 加载现有 Web 构建产物，系统托盘/桌面图标 |

## 三、技术选型对比与推荐（本地免费优先）

### 3.1 移动端 + 微信小程序：uni-app（推荐）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **uni-app（Vue3 语法）** | 一套代码编译 H5 / 微信小程序 / App 三端；本地免费；生态成熟（uv-ui 等多端 UI 库）；与现有 Vue3 心智一致 | 微信小程序仍需微信开发者工具预览/发布 | ✅ 推荐 |
| 原生微信小程序 | 微信能力最直接 | 单独一套代码，重复开发 | 不推荐 |
| Taro（React 语法） | 多端 | 与现有 Vue3 栈割裂 | 不推荐 |
| Flutter / React Native | App 体验最好 | 需新语言栈，成本高，非本地优先 | 第二批后可选 |

**小程序端页面结构（参照学习通）**：
- 底部 TabBar 四项：`首页`（学情概览卡片）/`课程`（课程列表 → 课程空间）/`消息`（通知与站内信）/`我的`（账号、目标、待办、错题本、会员）
- 首页：顶部轮播/横幅 + 学情概览卡片（GPA、预警数）+ 快捷工具宫格（签到、作业、试卷、答疑）
- 课程详情：顶部课程信息卡 → 章节列表（左侧章节目录样式）→ 任务 Tab（测验/签到/讨论/资料），下拉刷新
- 参照对象：学习通「首页-课程-消息-我」四 Tab 与课程内「章节/任务/更多」结构；作业帮「首页工具宫格 + 错题本 + 拍题」入口

### 3.2 Windows 桌面端：Electron（推荐）

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **Electron + electron-builder** | 免费开源；直接加载现有 Web 构建产物（`dist/`），代码零改动；NSIS 生成安装包/绿色版 | 安装包体积较大（约 80–150MB）；内存占用高于原生 | ✅ 推荐 |
| Tauri | 体积小、内存低 | 需 Rust 工具链，Windows 上需 WebView2，配置更重 | 备选 |

**桌面端实现**：新建 `desktop/` 目录，Electron 主进程加载 `web/dist/index.html`；应用图标/名称「学情预测分析系统」；菜单保留系统托盘，可最小化到托盘；打包为 Windows NSIS 安装包 + 免安装绿色版。

### 3.3 Web 端响应式改造（移动 H5）

现有 Element Plus 布局在窄屏（<768px）需要：
- 左侧菜单收起为抽屉（el-drawer）或顶部汉堡菜单；
- 表格改为卡片流/横向滚动；
- 弹窗全屏化（el-dialog 窄屏 `fullscreen`）；
- 底部增加移动端 Tab 快捷入口（可选）。
- 关键点：**先改布局壳（layout + 通用组件），业务页面按"先核心后外围"逐个适配**。

## 四、移动端 UI 设计规范（参照学习通/作业帮）

| 维度 | 规范 |
|---|---|
| 导航 | 底部固定 TabBar（≤5 项）；二级页顶部标题栏 + 返回；页面内用卡片分组 |
| 布局 | 单列卡片流，卡片间距 12px；内容区左右留 16px；不采用 PC 式多栏 |
| 字号 | 标题 17–18px / 正文 15–16px / 辅助 12–13px |
| 点击区 | 最小 44×44px；列表行高度 ≥ 48px |
| 交互 | 下拉刷新、上拉加载；加载态用骨架屏；签到码大字展示；警示色仅用于预警级别 |
| 表单 | 输入框全宽、大圆角；按钮全宽主操作 |
| 复用 | 统一使用移动端 UI 组件（uv-ui / uni-ui），不手写重复样式 |

## 五、分批实施计划

### 第一批：Web 响应式改造 + Windows 桌面端（Electron）
- 1a. Web 端响应式：layout 小屏抽屉菜单、表格卡片化兜底、弹窗全屏、全局 CSS 断点（<768px）
- 1b. 核心业务页移动适配：登录/注册、首页学情、课程空间（章节/资料/测验/签到/讨论）、作业、待办、通知
- 1c. Electron 桌面工程：`desktop/`（main + preload + electron-builder 配置），加载 `web/dist`，产出安装包与绿色版
- 验收：手机浏览器访问 Web 各核心页可用；桌面端安装后可打开并登录使用

### 第二批：微信小程序（uni-app 工程）
- 2a. 新建 `mini/` uni-app（Vue3 + uv-ui），配置底部 TabBar（首页/课程/消息/我的）
- 2b. 后端 API 按小程序需要补充适配（如微信登录 code2session 或账号绑定，先支持账号密码登录）
- 2c. 实现核心链路：登录 → 首页学情概览 → 课程空间（章节/任务/签到码签到/测验作答）→ 消息 → 我的（目标/待办/错题本）
- 2d. 微信开发者工具真机预览与联调
- 验收：微信开发者工具内可完整走通学生核心链路

### 第三批：移动端 App 与多端打磨
- 3a. 基于 uni-app 编译 Android/iOS App（本地打包或云打包），或先以 PWA 形式发布 H5
- 3b. 桌面端系统托盘/开机启动/版本提示等体验增强
- 3c. 多端一致性：接口版本、通知推送（小程序订阅消息/桌面通知）、错误兜底
- 验收：各端账号数据一致、预警/签到/作业闭环全通

## 六、风险与依赖

| 项 | 说明 |
|---|---|
| 微信小程序发布 | 需要小程序 AppID（个人/企业主体）与微信开发者工具；生产环境要求后端 HTTPS 域名 + 备案 |
| Electron 体积 | 安装包 80–150MB，可通过 asar 压缩与只加载本地资源控制 |
| 双工程 API 复用 | uni-app 与 Web 共用同一 REST API，注意 CORS 与 token 存储差异（小程序用 storage，无 localStorage） |
| 移动端权限 | 桌面端/小程序本地位于同一局域网即可访问本地后端；外网部署需公网地址 |
| 工作量 | 第一批以改造为主，1a–1c 即可交付可用的 H5 + 桌面端；第二批小程序为独立工程，工作量最大 |

## 七、待确认决策点（可先行默认，后续随时调整）

1. 第一批范围默认 =「Web 响应式（H5 可手机访问）+ Electron 桌面端」先行，小程序第二批再做 —— 若希望小程序优先，调整顺序即可。
2. 小程序登录默认先做「学号/工号 + 密码」登录（与 Web 一致），微信一键登录作为增强项。
3. 桌面端默认绿色免安装版 + NSIS 安装包两种产物。
